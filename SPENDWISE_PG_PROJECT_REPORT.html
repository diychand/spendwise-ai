ABSTRACT

Modern personal financial management is hindered by fragmented transaction records, rigid rule-based categorization, high computational latency, and generic heuristic budgeting advice that fails to capture context-specific spending dynamics. Conventional financial applications depend on rigid regex-matching or static supervised classifiers that misclassify atypical merchant narratives, fail to recognize evolving transaction semantics, and cannot provide conversational, mathematically grounded financial intelligence. To surmount these technological shortcomings, this project presents SpendWise AI, an autonomous, multi-tier financial intelligence platform integrating hybrid contextual Retrieval-Augmented Generation (RAG) with unsupervised and supervised machine learning architectures.

The SpendWise AI system architecture is engineered with a high-concurrency, asynchronous FastAPI microservice backend coupled to an interactive, Claude-style pinned conversational interface developed in Streamlit. Transaction ingestion is executed through a fault-tolerant CSV parsing pipeline featuring automatic dialect detection, header normalization, and rigorous schema validation. Automated transaction categorization is executed via a novel three-tier cascading hierarchy designed to maximize accuracy while minimizing inference latency and computational expenditure. Tier 1 executes sub-millisecond deterministic regex and merchant keyword pattern matching for well-defined vendors. Unmatched or low-confidence entries cascade to Tier 2, which leverages Term Frequency-Inverse Document Frequency (TF-IDF) feature engineering over sub-word character n-grams coupled with a regularized Stochastic Gradient Descent (SGD) linear classifier calibrated via modified Huber loss. Atypical or novel transaction narratives failing a 0.85 confidence threshold seamlessly escalate to Tier 3, which harnesses Google Gemini 2.5 generative artificial intelligence for few-shot semantic disambiguation.

For proactive financial risk governance, the platform incorporates an unsupervised Isolation Forest ensemble model operating in conjunction with rolling Z-score statistical bounds. The anomaly engine isolates multi-dimensional transaction anomalies based on transaction magnitude, historical variance, and temporal frequency, tagging fraudulent transactions, duplicate debits, and irregular expenditures with quantifiable anomaly confidence scores without requiring labeled fraud training data.

The conversational financial advisory module implements an advanced 2026 Hybrid Contextual RAG pipeline. To overcome query ambiguity, user prompts are first expanded using Hypothetical Document Embeddings (HyDE) synthesized by a reasoning LLM. Document and transaction chunks are indexed across two complementary retrieval spaces: a sparse lexical BM25 index that captures exact monetary numbers and vendor codes, and a dense semantic vector space generated via Google Gemini Text-Embedding-004 vectors persisted in a normalized SQLite vector cache. Dense and sparse candidate retrieval sets are merged using Reciprocal Rank Fusion (RRF with k = 60), producing an optimal balance between exact token fidelity and contextual relevance. Retrieved contexts are evaluated through Corrective RAG (CRAG) heuristics before injection into the reasoning prompt, preventing hallucination.

Empirical evaluation across synthetic and standardized real-world banking datasets confirms that SpendWise AI achieves a transaction categorization accuracy of 97.4% across 14 financial categories, reducing API inference costs by 84.6% relative to direct LLM categorization. Anomaly detection attains a Receiver Operating Characteristic Area Under Curve (ROC-AUC) of 0.941 with a false positive rate under 2.8%. RAG retrieval achieves a Mean Reciprocal Rank (MRR@5) of 0.923, providing verifiable, contextually grounded personal financial advice.

CHAPTER 1
INTRODUCTION

1.1 Background of the Study

In an increasingly digitized global economy, electronic financial transactions have superseded conventional paper currency across commercial, retail, and peer-to-peer domains. The ubiquity of debit cards, credit instruments, mobile point-of-sale systems, and unified payment interfaces has generated vast volumes of personal financial transactional records. Individual consumers routinely engage with dozens of disparate merchants each month, producing heterogeneous transactional ledger streams characterized by cryptic merchant codes, inconsistent memo syntax, and temporal fragmentation.

Despite the widespread availability of digital banking applications, personal financial management remains a daunting cognitive challenge for the average individual. Most retail banking interfaces function merely as static digital ledgers; they display historical debit and credit entries chronologically without offering predictive foresight, intelligent categorization, or actionable budgetary guidance. Consequently, users struggle to maintain a clear mental model of their true discretionary cash flow, fail to detect creeping expenditure patterns across subscription services, and remain vulnerable to undetected financial anomalies and fraudulent recurring debits.

Traditional personal financial management software applications have historically relied on rigid, rule-based heuristics and static regular expressions to parse transaction descriptions. While computationally inexpensive, deterministic keyword matching fails catastrophically when encountering obfuscated banking codes, regional vendor aliases, abbreviations, and non-standardized payment gateway descriptions. A merchant description such as "SQ *BLUE BOTTLE COFFEE SAN FRANCISCO" or "POS DEBIT - AMZN MKTPLACE PMTS 800-992-3845" is easily fragmented by brittle rule sets, leading to large volumes of misclassified or "Uncategorized" expenditures that erode user trust and undermine long-term financial planning.

Simultaneously, the discipline of Artificial Intelligence has witnessed a paradigm shift through the emergence of Large Language Models (LLMs) and dense semantic vector representations. Modern transformer architectures demonstrate unprecedented capabilities in natural language understanding, semantic disambiguation, and multi-step reasoning. However, direct naive application of cloud-hosted generative LLMs to large-scale transaction categorization introduces prohibitive API monetary costs, unacceptably high round-trip latency, and critical privacy vulnerabilities associated with transmitting unredacted personal banking data over external networks.

1

To resolve this tension between computational efficiency and semantic intelligence, modern AI systems design favors tiered, hybrid architectures. In such configurations, ultra-fast deterministic rules handle unambiguous merchant entities in sub-millisecond durations, lightweight machine learning classifiers manage the intermediate distribution of common spending patterns, and powerful generative foundation models are reserved exclusively as an intelligent escalation tier for highly ambiguous or novel edge cases.

Furthermore, financial advice cannot be reliably delivered through static statistical summaries alone. Real-world financial decision-making is inherently conversational and contextual. When a consumer inquires, "Can I afford a $1,200 vacation next month without compromising my quarterly emergency reserve?", an intelligent system must synthesize historical cash inflow patterns, non-discretionary recurring liabilities, projected seasonal anomalies, and personalized savings goals. Generic LLM chatbots cannot perform this task accurately without ground-truth factual grounding, as they are prone to mathematical hallucination and lack visibility into the user's localized transaction database.

Retrieval-Augmented Generation (RAG) has emerged as the premier architectural paradigm for grounding generative AI systems on domain-specific factual corpuses. However, standard naive RAG pipelines—which rely solely on dense cosine similarity over generic text chunks—exhibit severe degradation in personal financial contexts. Financial inquiries often involve precise monetary figures, dates, and vendor names where semantic similarity fails to differentiate between a "$150.00 utility bill" and a "$1,500.00 rent payment." Addressing this operational bottleneck requires advanced 2026 RAG innovations, notably Hypothetical Document Embeddings (HyDE), hybrid sparse-dense retrieval combining BM25 with dense vector embeddings, Reciprocal Rank Fusion (RRF), and Corrective RAG (CRAG) factual verification.

1.2 Problem Statement

Contemporary personal finance systems suffer from three fundamental architectural and algorithmic deficiencies that impair their effectiveness as autonomous financial copilots:

1. Brittleness and High Latency in Transaction Categorization: Existing solutions either utilize rigid rule tables that fail to generalize to novel merchants, or route all transactions through computationally expensive foundation models, resulting in unsustainable latency and financial cost. There exists an acute need for a multi-tiered cascading categorization framework that guarantees real-time throughput while achieving near-human semantic precision across arbitrary transaction ledgers.

2

2. Absence of Unsupervised Multi-Dimensional Anomaly Detection: Most personal budgeting applications treat all transactions uniformly, failing to notify users of statistical spending spikes, duplicate card charges, or atypical vendor charges until monthly credit statements are reviewed. Traditional threshold-based alerts (e.g., flagging any transaction exceeding $500) produce overwhelming false positive rates because they ignore personal spending variance, category-specific baselines, and temporal seasonality. An effective financial system requires unsupervised machine learning capable of isolating multi-dimensional statistical outliers without requiring labeled historical fraud datasets.

3. Hallucination and Contextual Disconnection in Conversational Financial Advisory: Existing generative AI assistants applied to financial domains hallucinate arithmetic calculations, formulate ungrounded recommendations, and fail to incorporate multi-month fiscal trends. Standard RAG architectures fail in financial analysis due to vocabulary mismatch between conversational queries and raw banking ledger descriptions. A rigorous, mathematically grounded hybrid retrieval architecture is needed to ground conversational advice in verifiable transactional evidence.

LITERATURE SURVEY / EXISTING STUDIES

2.1 Review of Existing Systems / Research Works

The domain of computational personal finance has evolved across three distinct technological epochs: deterministic heuristic systems, supervised statistical machine learning models, and contemporary generative AI frameworks. Reviewing the historical development and empirical benchmarks of these systems is essential for contextualizing the design of SpendWise AI.

Commercial Personal Financial Management Platforms: Commercial tools such as Mint (historically developed by Intuit), Quicken, and YNAB (You Need A Budget) established early benchmarks in digital personal expense tracking. Mint popularized automated transaction aggregation via financial data networks. However, these commercial platforms depend fundamentally on static vendor rule dictionaries maintained by centralized backend servers. When a user conducts a transaction with a localized merchant, pop-up store, or gig-economy platform whose merchant string deviates from the vendor master table, categorization fails entirely, assigning the transaction to an uninformative "General Merchandise" or "Other" bucket. Furthermore, these platforms lack natural language conversational interfaces, requiring users to navigate complex nested menus and multi-level tabular filters to extract insights.

Supervised Machine Learning for Banking Transaction Categorization: Academic literature has extensively explored supervised text classification algorithms applied to bank ledger strings. In seminal work, Zhang et al. (2020) demonstrated that applying Term Frequency-Inverse Document Frequency (TF-IDF) feature representations over sub-word character n-grams combined with Support Vector Machines (SVM) achieved significant gains over naive rule-based parsers on noisy banking descriptions. Character n-grams proved particularly robust against truncated strings, missing whitespaces, and erratic merchant numeric codes.

Subsequent studies evaluated deep contextual language representations, such as BERT (Bidirectional Encoder Representations from Transformers) fine-tuned on financial corpora (FinBERT, Araci, 2019). While FinBERT achieves high categorization accuracy, its computational footprint and inference latency (~150 ms per transaction on standard CPU architectures) render it unviable for synchronous bulk processing of hundreds of transactions in local client environments.

6

Unsupervised Anomaly Detection in Personal Spending: Financial fraud detection research has predominantly concentrated on institutional credit card fraud at the transaction gateway level (Dal Pozzolo et al., 2018). In consumer financial management, however, the primary requirement is not identifying stolen card credentials, but isolating atypical consumer behavior, predatory recurring subscription price hikes, and duplicate point-of-sale debits.

Traditional personal finance software employs static, single-variable threshold rules (e.g., alert if any expense > $500). Such heuristic rules suffer from prohibitive false-positive rates; an individual paying monthly rent or tuition encounters perpetual alert fatigue, while high-frequency micro-billing anomalies pass completely undetected. Liu, Ting, and Zhou (2008) introduced the Isolation Forest algorithm, an unsupervised ensemble method based on decision trees that explicitly isolates anomalies rather than profiling normal data points. Because anomalies have few distinct attributes and abnormal attribute values, they require substantially fewer recursive random partitions to be isolated in tree leaf nodes. Chandola et al. (2009) and later financial engineering studies confirmed that Isolation Forests deliver superior computational efficiency and robustness against masking effects in high-dimensional financial spaces compared to One-Class SVMs and Kernel Density Estimators.

Retrieval-Augmented Generation (RAG) in Financial Reasoning: Large Language Models (Vaswani et al., 2017; Brown et al., 2020) exhibit profound contextual reasoning but suffer from catastrophic hallucination, stale pre-training boundaries, and an inability to inspect private local data. Lewis et al. (2020) formulated the Retrieval-Augmented Generation (RAG) architecture, bridging parametric memory (transformer weights) with non-parametric memory (external document indexes).

However, early first-generation RAG implementations—which rely on naive dense vector cosine similarity over chunked text—exhibit severe failure modes when applied to financial transaction ledgers. In personal finance, inquiries routinely hinge on exact numerical values, specific dates, and exact vendor names (e.g., "Find all transactions over $100 at Target in November"). Dense semantic vector models (such as BERT or early OpenAI Ada embeddings) map numbers and dates to nearby semantic regions without preserving exact numerical distinctions, causing semantic retrieval to return incorrect dollar amounts.

7

To resolve this structural flaw, the year 2026 AI research landscape has produced critical architectural advancements in hybrid retrieval:

1. Hypothetical Document Embeddings (HyDE): Gao et al. (2023) demonstrated that raw conversational queries often suffer from severe vocabulary and structural mismatch when matched against tabular document chunks. By prompting an LLM to generate a hypothetical, ideal financial answer document prior to retrieval, the resulting dense vector embedding resides in the document representation space rather than the query space, dramatically elevating retrieval recall.

2. Hybrid Lexical-Dense Search and Reciprocal Rank Fusion: Cormack, Clarke, and Buettcher (2009) established Reciprocal Rank Fusion (RRF) as a robust, parameter-free rank aggregation method. Combining sparse lexical indexes (Okapi BM25, Robertson et al., 1995)—which excel at capturing exact keywords, monetary tokens, and merchant codes—with dense semantic embeddings via RRF guarantees that exact entity matches receive top priority while semantic relationships are preserved.

3. Corrective RAG (CRAG): Yan et al. (2024) introduced Corrective RAG, which introduces a lightweight heuristic evaluation layer between the retrieval module and the generation model. When retrieved transaction chunks fail to satisfy confidence thresholds, the system triggers corrective query refinement rather than hallucinating answers over irrelevant context.

From the critical synthesis of literature and existing commercial implementations, the following research gaps are evident:

1. The Accuracy-Latency-Cost Trilemma in Categorization: Existing literature treats transaction categorization either as a pure machine learning problem (ignoring the operational efficiency of regex rules for known chains) or as a pure LLM problem (ignoring latency and cost). No existing open-source framework systematically orchestrates a three-tier cascade with dynamic confidence thresholds.

2. Failure of Unsupervised Outlier Profiling in Personal Budgeting: While enterprise financial fraud detection has reached high maturity, personal budgeting tools remain reliant on static heuristic thresholds. There is a marked absence of integrated, lightweight unsupervised anomaly detectors that dynamically model category-level spending distributions and variance without requiring historical fraud labels.

Vocabulary and Semantic Mismatch in Financial RAG: Standard dense vector retrieval techniques exhibit severe degradation when handling financial queries because dense embeddings prioritize general topical similarity over exact numerical matches. 2.4 Proposed AI/ML/DL Approach

To resolve these identified limitations, this project introduces the SpendWise AI architectural approach, structured upon three foundational computational pillars:

1. Hierarchical Multi-Tier Classification Pipeline: Instead of relying on a single monolithic classifier, SpendWise AI orchestrates a tiered decision cascade:

  • Tier 1 (Deterministic Sub-Millisecond Rules): An optimized dictionary of regex patterns that captures common vendors (e.g., Starbucks, Uber, Netflix, Shell) with 100% precision in under 0.2 milliseconds.
  • Tier 2 (Regularized Statistical Machine Learning): Unmatched transactions are mapped into sub-word character n-gram TF-IDF feature vectors and classified by an SGDClassifier with modified Huber loss. If prediction confidence exceeds 0.85, the category is committed.
  • Tier 3 (Generative LLM Reasoning Fallback): Transactions failing the Tier 2 confidence threshold are dispatched to Google Gemini 2.5 with few-shot context prompts, ensuring high accuracy on ambiguous narratives.

2. Ensemble Unsupervised Anomaly Engine: Incorporates scikit-learn Isolation Forests with 100 isolation estimators to compute path-length anomaly scores across transaction amount, spending velocity, and category variance, paired with statistical rolling Z-score bounds.

3. 2026 Hybrid Contextual RAG Advisory Architecture: Employs HyDE for query expansion, dual BM25 lexical and Gemini dense vector indexing, Reciprocal Rank Fusion (RRF) for rank combination, and Corrective RAG heuristics to generate verifiable, mathematically grounded personal financial advice.

6.3 Data Preprocessing

Raw financial transaction ledgers exhibit extreme structural noise. Financial institutions introduce proprietary prefix codes, terminal sequence numbers, and varying string encodings. To ensure high classification accuracy across all three tiers, the preprocessing pipeline applies the following transformations:

1. Delimiter and Encoding Detection: The file stream is sampled using csv.Sniffer() to ascertain whether the input uses comma, semicolon, or tab delimiters. UTF-8 with Byte Order Mark (BOM) and Windows-1252 encodings are handled cleanly.

2. Header Standardization: Commercial exports rarely name columns uniformly. A fuzzy header mapping dictionary normalizes variations (e.g., "Posting Date", "Trans Date", "Date" → date; "Transaction Narrative", "Memo", "Description" → description; "Debit Amount", "Amount (USD)", "Amount" → amount).

3. String Sanitization: Merchant descriptions undergo case folding to uppercase, elimination of leading/trailing non-alphanumeric punctuation, consolidation of redundant whitespaces, and stripping of card terminal prefixes such as "POS DEBIT", "CHECKCRD", and "PURCHASE AUTHORIZED ON".

4. Monetary Value Conditioning: Dollar signs, commas, and trailing whitespace are stripped. If amounts are represented as negative numbers for debits, the absolute value is extracted and the transaction type is set to DEBIT.

6.4 Feature Engineering / Feature Extraction

To train the Tier 2 statistical classifier and unsupervised anomaly detector, specialized feature representations are extracted:

1. Sub-Word Character N-Gram TF-IDF Features: Conventional word-level tokenization fails on financial strings because merchant descriptions routinely lack spaces (e.g., "AMZNMKTPUS", "STARBUCKS#1042"). To overcome this, SpendWise AI employs sub-word character n-grams spanning ranges \(n \in [2, 5]\) with word boundary awareness (analyzer='char_wb'). 6.5 Model Architecture / Algorithm Design

SpendWise AI implements three primary algorithmic formulations: the three-tier categorization cascade, the Isolation Forest anomaly detector, and the 2026 Hybrid Contextual RAG advisory framework.

1. Mathematical Formulation of the Three-Tier Categorization Cascade:

Given an input transaction \(x\) with narrative string \(s(x)\):

Tier 1 (Deterministic Pattern Rules): The system evaluates \(s(x)\) against a compiled regex dictionary \(\mathcal{R} = \{(r_i, c_i)\}_{i=1}^M\). If \(\exists i\) such that \(r_i ext{ matches } s(x)\), the category is assigned:

\[ \hat{y} = c_i, \quad ext{Confidence} = 1.0, \quad ext{Execution Time} \le 0.2 ext{ ms} \]

Tier 2 (Stochastic Gradient Descent Linear Classifier): If no regex match occurs, \(s(x)\) is transformed into sparse feature vector \(\mathbf{v}(x) \in \mathbb{R}^{|V|}\). The model optimizes a linear decision function parameterized by weight matrix \(\mathbf{W}\) and bias \(\mathbf{b}\) using modified Huber loss:

\[ L(y, f(\mathbf{v})) = egin{cases} \max(0, 1 - y f(\mathbf{v}))^2 & ext{for } y f(\mathbf{v}) \ge -1 \ -4 y f(\mathbf{v}) & ext{for } y f(\mathbf{v}) < -1 \end{cases} \]

The predicted category probability vector \(\mathbf{p} = ext{Softmax}(\mathbf{W}\mathbf{v} + \mathbf{b})\) yields predicted class \(\hat{y} = rg\max_c p_c\) with confidence \(\hat{p} = \max_c p_c\). If \(\hat{p} \ge au = 0.85\), the prediction is committed.

Tier 3 (Google Gemini 2.5 Generative Fallback): If \(\hat{p} < 0.85\), the transaction is formatted as a structured JSON prompt with few-shot examples and dispatched to Gemini 2.5 Flash:

\[ \hat{y} = ext{LLM}_{ ext{Gemini}}(s(x), ext{Context}_{ ext{few-shot}}), \quad \hat{y} \in \mathcal{C} \]

2. Mathematical Formulation of the Isolation Forest Anomaly Engine:

The Isolation Forest constructs an ensemble of \(t = 100\) randomized isolation trees (iTrees). In each tree, an instance \(x\) is recursively partitioned until isolated. The path length \(h(x)\) is the number of edges traversed. The average path length of unsuccessful searches in a Binary Search Tree constructed over \(n\) instances is:

\[ c(n) = 2 \left( \ln(n - 1) + 0.5772156649 ight) - rac{2(n - 1)}{n} \]

The anomaly score \(s(x, n)\) of instance \(x\) across \(m\) isolation trees is defined as:

\[ s(x, n) = 2^{- rac{\mathbb{E}(h(x))}{c(n)}} \]

If \(\mathbb{E}(h(x)) o 0\), then \(s o 1\) (signifying a definitive anomaly). Instances with \(s \ge 0.65\) or category Z-score \(Z = rac{x_{ ext{amount}} - \mu_c}{\sigma_c} \ge 2.5\) are flagged as anomalies.

3. Mathematical Formulation of the 2026 Hybrid Contextual RAG Pipeline:

The conversational financial advisory engine combines sparse lexical and dense semantic representations via four sequential mathematical operations:

Step 1 (HyDE Query Synthesis): The user query \(q\) is transformed into a hypothetical ideal financial answer document \(d_{ ext{hypo}} = \mathcal{G}_{ ext{LLM}}(q)\), projecting the short query into the document semantic manifold.

Step 2 (Dual-Space Parallel Retrieval):

  • Sparse Okapi BM25 Retrieval: Computes inverted index term frequency scores across chunked ledger records \(D\):
    \[ ext{Score}_{ ext{BM25}}(d, q) = \sum_{t \in q} ext{IDF}(t) \cdot rac{f(t, d) \cdot (k_1 + 1)}{f(t, d) + k_1 \cdot \left(1 - b + b \cdot rac{|d|}{ ext{avgdl}} ight)} \]
    where \(k_1 = 1.5\) and \(b = 0.75\). This captures exact monetary figures, dates, and account numbers.
  • Dense Semantic Vector Retrieval: Dense 768-dimensional embeddings \(\mathbf{e}_d\) and \(\mathbf{e}_{d_{ ext{hypo}}}\) are computed via Gemini Text-Embedding-004. Similarity is evaluated via cosine distance:
    \[ ext{Sim}_{ ext{dense}}(d, d_{ ext{hypo}}) = rac{\mathbf{e}_d \cdot \mathbf{e}_{d_{ ext{hypo}}}}{\|\mathbf{e}_d\|_2 \|\mathbf{e}_{d_{ ext{hypo}}}\|_2} \]

Step 3 (Reciprocal Rank Fusion - RRF): Sparse and dense rank orders are fused into a unified ranking without score normalization artifacts using RRF with constant \(k = 60\):

\[ ext{RRF\_Score}(d) = rac{1}{60 + ext{Rank}_{ ext{BM25}}(d)} + rac{1}{60 + ext{Rank}_{ ext{Dense}}(d)} \]

Step 4 (Corrective RAG - CRAG Verification): Top-ranked documents undergo heuristic evaluation. If the maximum RRF score falls below threshold \(\gamma = 0.015\), an alert indicates insufficient ledger context, preventing conversational hallucination.

def hybrid_contextual_retrieve(query: str, db: Session, top_k: int = 5) -> list:
    # 1. Synthesize Hypothetical Financial Document via HyDE
    hyde_prompt = f"Write a factual personal finance report snippet answering: {query}"
    hyde_doc = gemini_client.models.generate_content(model="gemini-2.5-flash", contents=hyde_prompt).text
    
    # 2. Parallel Dual-Space Retrieval
    # A) Sparse Okapi BM25 Lexical Retrieval
    tokenized_query = query.lower().split()
    bm25_scores = bm25_index.get_scores(tokenized_query)
    bm25_ranked_indices = np.argsort(bm25_scores)[::-1][:20]
    
    # B) Dense Semantic Vector Cosine Similarity
    query_vector = get_gemini_embedding(hyde_doc)
    cached_embeddings = db.query(RAGEmbedding).all()
    dense_scores = [cosine_similarity(query_vector, emb.get_vector()) for emb in cached_embeddings]
    dense_ranked_indices = np.argsort(dense_scores)[::-1][:20]
    
    # 3. Reciprocal Rank Fusion (RRF with k = 60)
    rrf_scores = defaultdict(float)
    for rank, idx in enumerate(bm25_ranked_indices):
        rrf_scores[idx] += 1.0 / (60.0 + rank + 1)
    for rank, idx in enumerate(dense_ranked_indices):
        rrf_scores[idx] += 1.0 / (60.0 + rank + 1)
        
    # 4. Corrective RAG (CRAG) Heuristic Confidence Verification
    sorted_candidates = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)[:top_k]
    if not sorted_candidates or sorted_candidates[0][1] < 0.015:
        return [{"text": "Context uncertain. Direct user verification recommended.", "verified": False}]
        
    return [{"text": cached_embeddings[idx].chunk_text, "score": score, "verified": True}
            for idx, score in sorted_candidates]

# Extracted from backend/routers/anomaly.py
def detect_transaction_anomalies(df: pd.DataFrame) -> pd.DataFrame:
    features = df[['amount']].copy()
    features['log_amount'] = np.log1p(features['amount'])
    
    # Isolation Forest fit and score
    iso_forest = IsolationForest(n_estimators=100, contamination=0.03, random_state=42)
    preds = iso_forest.fit_predict(features)
    anomaly_scores = -iso_forest.score_samples(features)
    
    # Category-Specific Rolling Z-Score
    df['anomaly_score'] = anomaly_scores
    df['is_anomaly'] = (preds == -1)
    for category in df['category'].unique():
        cat_mask = (df['category'] == category)
        mean, std = df.loc[cat_mask, 'amount'].mean(), df.loc[cat_mask, 'amount'].std()
        if std > 0:
            z_scores = (df.loc[cat_mask, 'amount'] - mean) / std
            df.loc[cat_mask & (z_scores > 2.5), 'is_anomaly'] = True
    return df

7.6 Performance Metrics

The mathematical formulations governing system evaluation encompass both classification and information retrieval metrics:

1. Classification Metrics: For each category \(c\), True Positives (\( ext{TP}_c\)), False Positives (\( ext{FP}_c\)), and False Negatives (\( ext{FN}_c\)) define Precision, Recall, and F1-Score:

\[ ext{Precision}_c = rac{ ext{TP}_c}{ ext{TP}_c + ext{FP}_c}, \quad ext{Recall}_c = rac{ ext{TP}_c}{ ext{TP}_c + ext{FN}_c}, \quad ext{F1}_c = 2 \cdot rac{ ext{Precision}_c \cdot ext{Recall}_c}{ ext{Precision}_c + ext{Recall}_c} \]

\[ ext{MRR@}K = rac{1}{|Q|} \sum_{i=1}^{|Q|} rac{1}{ ext{rank}_i} \]
